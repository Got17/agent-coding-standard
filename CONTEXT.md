# Domain Context & Glossary

## Glossary

- **Standard**: A documented set of production-grade architectural rules, coding practices, and deployment guidelines for software projects.
- **Agent Rule / Prompt**: Machine-readable guidelines and context files designed to be consumed by AI coding agents (e.g., Antigravity, Claude Code, Codex).
- **Agent Template (AGENTS.md)**: A copy-pasteable, self-contained rule block designed to be copied directly into target projects' `AGENTS.md` file so an AI agent immediately adheres to the team's standards.
- **Documentation Site**: Web portal generated from Markdown files serving human developers.
- **JWT (JSON Web Token)**: Signed token format that can carry identity and authorization claims; optional implementation choice, not the required session mechanism.
- **OIDC (OpenID Connect)**: Identity layer on OAuth 2.0 used to authenticate users and communicate identity claims.
- **OAuth 2.0**: Delegated authorization framework for issuing access tokens to clients.
- **MFA (Multi-Factor Authentication)**: Authentication using factors from different categories, such as knowledge plus possession or biometric factors.
- **RBAC (Role-Based Access Control)**: Authorization model based on assigned roles such as `admin`, `editor`, or `viewer`.
- **ABAC (Attribute-Based Access Control)**: Authorization model based on attributes such as tenant, resource status, ownership, risk, or environment.
- **ReBAC (Relationship-Based Access Control)**: Authorization model based on relationships between subjects and resources, such as owner, member, manager, or parent account.
- **BOLA (Broken Object Level Authorization)**: Authorization flaw where a requester can access a specific object they are not allowed to access.
- **IDOR (Insecure Direct Object Reference)**: BOLA-style flaw where changing or guessing an object reference exposes another user's or tenant's resource.
- **BFF (Backend for Frontend)**: Server-side layer dedicated to one frontend that can keep tokens and backend credentials out of browser-executed code.
- **CSRF (Cross-Site Request Forgery)**: Attack where a malicious site causes a user's browser to send an authenticated state-changing request to a trusted site.
- **XSS (Cross-Site Scripting)**: Injection flaw that allows attacker-controlled JavaScript to execute in an application's origin.
- **CORS (Cross-Origin Resource Sharing)**: Browser-controlled protocol for allowing or denying JavaScript calls between different origins.
- **AAL (Authenticator Assurance Level)**: NIST term for the strength of an authentication event.
- **Secret**: Any value that grants access, proves identity, signs trust, decrypts data, or enables privileged operations.
- **Secret Store / Vault**: Managed system for storing, retrieving, auditing, rotating, and revoking secrets.
- **KMS (Key Management Service)**: Managed service or module that protects cryptographic keys and performs key operations.
- **Envelope Encryption**: Pattern where data is encrypted with a data key, and that data key is encrypted by a higher-level KMS key.
- **Workload Identity**: Cloud, cluster, or platform identity assigned to a running service so it can access resources without static credentials.
- **Dynamic Secret**: Short-lived credential generated on demand for a specific workload, role, and time window.
- **Static Secret**: Long-lived credential that exists until rotated or revoked.
- **Rotation**: Replacing a secret with a new value and moving consumers safely to the new value.
- **Revocation**: Invalidating a secret so it can no longer be used.
- **Break-Glass Access**: Emergency human access path used when normal automated access is unavailable; it must be time-bound, approved, and audited.
- **Secret Scanning**: Automated detection of likely secrets in source code, commits, pull requests, CI logs, or artifacts.
- **Push Protection**: Pre-receive or hosted-source-control control that blocks commits containing detected secrets before they enter repository history.
- **Expand-Migrate-Contract**: Pattern for zero-downtime database schema changes where changes are executed in three non-breaking phases (Expand schema, Migrate data, Contract old schema).
- **Connection Pool**: Reusable pool of database connections maintained to reduce connection overhead and bound concurrent database load.
- **N+1 Query Problem**: Performance antipattern where an application executes 1 initial query to fetch $N$ parent records followed by $N$ individual queries to fetch child data.
- **Statement Timeout**: Server-side database configuration limiting the maximum execution time of any single query to prevent long-running locks and connection exhaustion.
- **Trace Context Propagation**: Practice of serializing and forwarding distributed tracing identifiers (`traceparent` header carrying `trace_id` and `span_id`) across HTTP, gRPC, and message queue boundaries.
- **Liveness Probe**: Lightweight endpoint (`/healthz/liveness`) indicating whether a service process is alive and responsive; failure triggers container restart.
- **Readiness Probe**: Dependency check endpoint (`/healthz/readiness`) indicating whether a service can process traffic (verifying DB, cache, and queue connections); failure removes the container from load balancer routing.
- **Golden Signals**: Four key metrics (Latency, Traffic, Errors, Saturation) defined in Google SRE guidelines for monitoring distributed systems.
- **Circuit Breaker**: Pattern that monitors downstream call failures and trips open to fail fast when error thresholds are exceeded, preventing cascading system failures.
- **Exponential Backoff with Jitter**: Retry strategy that increases delay exponentially after each failed attempt and adds random variance (jitter) to prevent thundering herd / retry storms.
- **Cache-Aside Pattern**: Caching pattern where application code first checks the cache, loads from the database on cache miss, and writes the fetched result back to the cache with a TTL.
- **Cache Stampede (Thundering Herd)**: Performance issue where multiple concurrent requests simultaneously compute and write the exact same cache miss value, exhausting database resources.
- **AsyncLocalStorage**: Node.js `node:async_hooks` primitive used to store and propagate request-scoped store context (such as `trace_id` or `user_id`) across asynchronous call chains.
- **Strict Null Checks**: TypeScript compiler flag (`strictNullChecks`) that prevents assigning `null` or `undefined` to typed variables unless explicitly declared as a union type.
- **Pydantic v2**: High-performance Python data validation and serialization library powered by Rust core, enforcing type hints at runtime.
- **FastAPI Threadpool Offloading**: FastAPI execution behavior where standard synchronous `def` endpoints are automatically offloaded to an underlying threadpool worker thread to avoid blocking the main `asyncio` event loop.

## Architectural Decisions Log

- **Doc Engine**: Markdown-based files rendered into a static site (VitePress/Starlight) while maintaining raw machine-readable structures for AI agents.
- **Primary Audience**: Human developers and AI coding agents.
- **Distribution Model**: Dual format per standard — Human-readable documentation + Portable `AGENTS.md` prompt blocks for instant project copying.
- **Repository Structure**: Option A — Separated `docs/` (for static site & human reading) and `templates/` (for copy-pasteable `AGENTS.md` files).
- **Doc Engine**: VitePress configured in `docs/.vitepress/config.mjs` and synced at root (`.vitepress/config.mjs`) serving `docs/`.
- **AGENTS Templates Web Routes**: Standardized in `docs/templates/` with web links updated in `docs/templates-index.md`.
- **AGENTS-backend Scope**: Language-agnostic universal production baseline for backend services. Framework/language-specific details are handled inside the generic templates or project-level AGENTS.md files — no framework-specific template files are maintained in this repo.
- **AGENTS-backend Pillars**: Strictly universal invariants across 7 pillars: (1) Architecture & Layering, (2) Security & Auth Baseline, (3) Data & Persistence, (4) Observability & Telemetry, (5) Resilience & Traffic Control, (6) Testing & QA, (7) Code Quality, Maintainability & Documentation.
- **AGENTS-backend API Invariants**: Unified 5-key error JSON envelope (`code`, `message`, `details`, `timestamp`, `request_id`) and Zero-Trust boundary input validation (rejecting unexpected fields with 400 Bad Request).
- **AGENTS-backend Database Safety**: Strict Expand-Migrate-Contract zero-downtime migrations, parameterized SQL only, N+1 query ban with statement timeouts, zero network I/O inside DB transactions, and mandatory 4-key audit metadata (`created_at`, `updated_at`, `created_by`, `updated_by`).
- **AGENTS-backend Operations & Testing**: Structured JSON logging with trace/correlation ID context, automatic PII masking, dual health probes (`/healthz/liveness`, `/healthz/readiness`), explicit network timeouts, graceful SIGTERM shutdown with 30s drain, containerized integration tests, and CI contract diff checks.
- **AGENTS-backend Code Quality & Documentation**: Mandatory 7th pillar adding SOLID, pragmatic DRY, YAGNI/KISS simplicity, guard clauses (early exits), intent-based comments (why not what), and docstring/contract synchronization.
- **AGENTS-backend Generalization Updates (post-review)**: Backend template now supports machine-checkable contracts beyond REST/gRPC (`OpenAPI 3.1`, `Protobuf`, `GraphQL`, `AsyncAPI`, or equivalent), clarifies auth as credential/session verification rather than purely stateless JWT, scopes BOLA rules to protected user/tenant data with documented public/system exceptions, treats `READ COMMITTED` as relational-specific with non-relational consistency equivalents, prefers OpenTelemetry-compatible telemetry without banning vendor agents, and treats testing ratios as targets rather than quotas.
- **Auth & Session Standard Scope**: Browser-facing apps prefer secure server-backed sessions or opaque tokens in `HttpOnly`, `Secure`, `SameSite=Lax/Strict` cookies; JWT is optional; authorization is centralized, deny-by-default, and object-scoped; cookie-authenticated mutations require CSRF protection beyond `SameSite`; admin/high-risk accounts require MFA and sensitive operations require step-up or reauthentication.
- **Secrets Management Standard Scope**: Production secrets live in managed secret stores or approved encrypted GitOps mechanisms, are injected only at runtime, are accessed through least-privilege workload identities, have owner/purpose/rotation/revocation metadata, and are never displayed, committed, logged, or copied by AI agents.
- **Database & Persistence Standard Scope**: Versioned schema migrations using Expand-Migrate-Contract zero-downtime pattern with CI drift linting; strict query parameterization (OWASP A03:2021 SQLi ban); foreign key indexing & explicit `ON DELETE` cascade/restrict policies; N+1 query prevention; bounded connection pools (`statement_timeout`, `lock_timeout`, `idle_in_transaction_session_timeout`); zero external network I/O inside DB transactions; READ COMMITTED isolation default; Optimistic Concurrency Control (`version` column) & Pessimistic Locking (`FOR UPDATE`); mandatory 4-key audit metadata (`created_at`, `updated_at`, `created_by`, `updated_by`); and soft deletes via `deleted_at` with partial unique indexes (`WHERE deleted_at IS NULL`).

- **Logging & Telemetry Standard Scope**: Mandatory structured JSON logging (`timestamp` ISO-8601, `level`, `service`, `message`, `trace_id`, `span_id`, `request_id`); ban on plain text/unstructured print statements; W3C TraceContext propagation across HTTP/gRPC/queues; automated PII and secret redaction; dual health check probes (`/healthz/liveness` process check without DB calls, `/healthz/readiness` dependency check); OpenTelemetry (OTLP) metrics baseline for Google SRE 4 Golden Signals.
- **Resilience & Caching Standard Scope**: Explicit connect/read network timeouts (max 2-5s); exponential backoff retries with randomized jitter (max 2-3 retries, no 4xx retries); Circuit Breaker state machines (Closed, Open, Half-Open) & Bulkhead concurrency isolation per downstream dependency; token bucket rate limiting with HTTP 429 `Retry-After` headers; 30s graceful SIGTERM shutdown with connection draining; Cache-Aside strategy with mandatory explicit TTLs; and single-flight request coalescing for cache stampede protection.
- **Node.js & TypeScript Standard Scope**: Strict compiler flags (`"strict": true`, `"noUncheckedIndexedAccess": true`, `"strictNullChecks": true`); native ES Modules (`ESM`); zero synchronous main event loop blocking; Zod/Valibot boundary schema validation; `AsyncLocalStorage` for request correlation context; process `unhandledRejection` and `uncaughtException` graceful exit handling; custom `ApplicationError` hierarchy.
- **Python & FastAPI Standard Scope**: Target Python 3.11+ with strict type hinting (`mypy --strict` / `ruff`); dependency management via `uv` / `Poetry` lockfiles; strict event loop hygiene (`async def` reserved exclusively for async I/O, sync tasks in standard `def` threadpool handlers); Pydantic v2 `extra='forbid'` boundary validation; `pydantic-settings` with `SecretStr` credential masking; and FastAPI `Depends()` layered architecture.
- **AGENTS-frontend Scope**: Universal production baseline for frontend web applications. Framework/meta-framework-specific rules (e.g., Next.js RSC, App Router) are handled inside project-level AGENTS.md files — no framework-specific template files are maintained in this repo.
- **AGENTS-frontend Pillars**: 7 core pillars: (1) Component Architecture & Layering, (2) State Management & Data Fetching, (3) Web Performance & Core Web Vitals, (4) Security & Auth Baseline, (5) Accessibility (a11y) & UX Invariants, (6) Testing Strategy & QA, (7) Code Quality, CSS Maintainability & Design Tokens.
- **AGENTS-frontend Pillar 1 (Component Architecture)**: Strict pure presentation vs container/hook logic separation, immutable typed props contracts (`type`/`interface`), ~150-line / max 3 state limit per component, and named exports baseline.
- **AGENTS-frontend Pillar 2 (State & Data Fetching)**: Decouple server state (async cache) from client UI state, zero state duplication into local component state, explicit mutation invalidation keys/optimistic rollbacks, and retry caps with localized error boundaries.
- **AGENTS-frontend Pillar 3 (Performance & Web Vitals)**: Strict Core Web Vitals SLA (LCP <= 2.5s, INP <= 200ms, CLS <= 0.1 at p75 mobile), dynamic import code-splitting for heavy components, zero CLS via explicit image dimensions/aspect ratios, path-level tree-shakeable imports, and font-display swap.
- **AGENTS-frontend Pillar 4 (Security & Auth Baseline)**: DOMPurify-sanitized HTML injection only, no tokens/PII in localStorage (httpOnly SameSite cookies required), same-origin whitelist on redirects, and CSP/X-Frame-Options/HSTS headers enforced.
- **AGENTS-frontend Pillar 5 (Accessibility & UX)**: WCAG 2.2 AA minimum (4.5:1 contrast), full keyboard navigation via WAI-ARIA patterns, no outline:none without accessible replacement, semantic HTML over div+ARIA, and aria-live announcements for async feedback states.
- **AGENTS-frontend Pillar 6 (Testing & QA)**: 60% unit (hooks/logic), 30% component tests via Testing Library (getByRole over getByTestId), 10% E2E smoke; MSW for network interception, fake timers for async, and mandatory CRUD + auth + error boundary E2E coverage.
- **AGENTS-frontend Pillar 7 (Code Quality & CSS Architecture)**: Design token baseline (CSS variables for colors/spacing), scoped CSS co-location, early-return guard clauses (no nested ternary JSX), pragmatic DRY/YAGNI, and intent-based comments.
- **Deployment Standard**: Static site deployment via Vercel (or Dokploy PaaS) publishing `docs/.vitepress/dist` with `cleanUrls: true` enabled via root `vercel.json`.
- **AGENTS-frontend Additional Rules (post-review)**: Three rules added post-review: (1) Error Boundary Telemetry — boundary errors MUST be sent to observability service (Sentry/Datadog), not swallowed; (2) URL as Authoritative State — shareable UI state SHOULD live in URL search params, not useState/global store; (3) Visual Regression Testing — SHOULD run Chromatic/Percy/Playwright snapshots on design-token and shared component PRs.
- **AGENTS-frontend Generalization Updates (post-review)**: Frontend template now aligns Core Web Vitals with inclusive good thresholds (`LCP <= 2.5s`, `INP <= 200ms`, `CLS <= 0.1`), limits `fetchpriority="high"` and preload guidance to likely/late-discovered LCP assets, updates accessibility baseline to WCAG 2.2 AA, treats browser token storage with BFF/httpOnly-cookie preference plus memory/service-worker fallback for unavoidable browser-held access tokens, treats test ratios as targets rather than quotas, scopes automated axe checks to changed interactive components and critical page states with manual accessibility checks for key flows, and allows literal CSS values for clear technical one-offs while preserving design-token discipline for product styling.
- **AGENTS-fullstack Scope**: Universal production baseline bridging frontend and backend layers for fullstack applications. Covers 8 core pillars: (1) Workspace & Monorepo Layout, (2) End-to-End Type Safety & API Contracts, (3) SSR/Hydration & State Synchronization, (4) Fullstack Auth Session Propagation & Security, (5) E2E Testing & QA Pipelines, (6) Observability & Distributed Trace Propagation, (7) Build, Migration & Deployment Orchestration, (8) Code Quality, Maintainability & Documentation.
- **AGENTS-fullstack Pillar 1 (Workspace & Monorepo Layout)**: Strict package/module boundaries (`@project/types`, `@project/shared-schemas`, `@project/api-client`, `@project/server`); `server-only` guards and export map restrictions to prevent server secrets and server-only code from entering client bundles; client env vars must use framework prefixes (NEXT_PUBLIC_, VITE_) and must never contain secrets.
- **AGENTS-fullstack Pillar 2 (E2E Type Safety & Contracts)**: Shared single source of truth for validation schemas (e.g. Zod/Valibot or OpenAPI 3.1) across server handlers and UI forms/SDKs; zero-type-drift contract validation in CI; mass assignment prevention via explicit write allowlists (BOPLA).
- **AGENTS-fullstack Pillar 3 (SSR & State Synchronization)**: Strict state boundaries — URL search parameters as authoritative UI state; server data hydrated directly into async client cache (TanStack Query/SWR) without duplicating into component `useState`; mandatory mutation key invalidation or optimistic rollback patterns; client-generated idempotency keys on non-idempotent cross-boundary mutations.
- **AGENTS-fullstack Pillar 4 (Auth & Security)**: `httpOnly`, `Secure`, `SameSite` cookies as primary session transport (JWTs in `localStorage` strictly banned); anti-CSRF protection (double-submit cookies / custom header tokens) on non-GET mutations; strict CORS origin whitelisting for decoupled origins; BOLA/IDOR prevention — server queries scoped by authenticated user/tenant ID from token context.
- **AGENTS-fullstack Pillar 5 (E2E Testing & QA Pipelines)**: Playwright/Cypress E2E test suites exercising complete UI -> API -> Database flows in isolated ephemeral databases with deterministic seeding; Playwright `storageState` for auth context reuse; OpenAPI/schema contract diff validation in CI.
- **AGENTS-fullstack Pillar 6 (Observability & Distributed Tracing)**: W3C `traceparent` / correlation ID header propagation from browser fetch calls through server handlers to structured backend logs; client error boundary telemetry forwarded to centralized platform (Sentry/Datadog) with session ID and trace_id; dual health probes (/healthz/liveness + /healthz/readiness); OpenTelemetry SDK instrumentation across server and BFF layers.
- **AGENTS-fullstack Pillar 7 (Deployment Orchestration)**: Expand-Migrate-Contract database schema migrations executed prior to application code deployment; immutable static asset hashing; pre-flight smoke test gates in CI/CD before zero-downtime traffic cutover; graceful SIGTERM/SIGINT shutdown with 30s in-flight drain and clean DB/cache connection release.
- **AGENTS-fullstack Pillar 8 (Code Quality, Maintainability & Documentation)**: SOLID alignment (SRP per shared module, DIP via injected interface abstractions); pragmatic DRY/YAGNI with no speculative abstractions; guard clauses over deep nesting in both server handlers and UI render logic; intent-based comments (why not what); contract and docstring sync with shared OpenAPI/Protobuf/GraphQL specs.
- **Template Granularity Decision**: Framework-specific AGENTS templates (AGENTS-nodejs, AGENTS-fastapi, AGENTS-nextjs, AGENTS-go) have been removed. The repo ships only generic role-based templates (backend, frontend, fullstack, devops). Framework/language-specific rules belong in individual project AGENTS.md files, not in this shared standards repo.
- **AGENTS-devops Scope**: Universal production baseline for DevOps, CI/CD pipelines, containerization, and cloud infrastructure management. Covers 8 core pillars: (1) Infrastructure as Code (IaC) & Immutable Infrastructure, (2) Container Security & Image Optimization, (3) CI/CD Automation & Pipeline Guardrails, (4) Deployment, GitOps & Orchestration (Kubernetes/Dokploy), (5) Security, Secrets Management & Zero-Trust Access, (6) Observability, Logging & Alerting Baseline, (7) Resilience, Disaster Recovery & High Availability, (8) Scripting, Automation & Code Quality Rules.
- **Go Backend Standard Scope**: Source-backed Go REST API standard using hexagonal architecture. Maintains Go-specific guidance in `docs/backend/go-rest-hexagonal.md` while preserving the repository decision that distributed AGENTS templates remain role-based and generic.
- **Go Hexagonal Backend Invariants**: `cmd/<service>/main.go` is the composition root; `internal/domain` and `internal/app` stay framework/infrastructure-free; adapters for HTTP, SQL, cache, queues, and external clients depend inward; interfaces live in consumer packages; every request-scoped operation accepts `context.Context` first; production gates include formatting, tests, race detection where supported, and `govulncheck`.
- **Next.js Frontend Structure Standard Scope**: Source-backed App Router project structure standard in `docs/frontend/nextjs-frontend-structure.md`, covering `src/app`, route groups, private folders, Server/Client Component boundaries, server-only data access, feature modules, metadata/assets/env handling, and production CI gates.
- **Next.js Structure Invariants**: New Next.js frontend projects use App Router under `src/app`; public routes require `page.tsx` or `route.ts`; route groups organize without changing URLs; `_` private folders hold segment-local implementation details; shared code lives outside `app`; Server Components are default; `"use client"` is limited to interaction/browser API boundaries; server-only modules are guarded and never imported by Client Components.
- **API Design Standard Scope**: Machine-checkable contracts (OpenAPI 3.1, Protobuf, GraphQL, AsyncAPI); RFC 9110 HTTP method semantics; `kebab-case` paths & `snake_case` query/JSON parameters; OWASP API3:2023 mass-assignment rejection (`unevaluatedProperties: false`); standard flat 5-key error envelope correlated with W3C `traceparent`; and explicit deprecation/sunset lifecycle headers (RFC 9745 & RFC 8594).
- **Node.js & TypeScript Invariants**: `tsconfig.json` `"strict": true`, `"noUncheckedIndexedAccess": true`, `"exactOptionalPropertyTypes": true`, `"moduleResolution": "NodeNext"`; native ESM (`"type": "module"`) with explicit `.js` import extensions; deterministic package lockfiles; zero main event loop blocking (Worker Threads for CPU tasks); Zod strict boundary schema validation (`.strict()`); `AsyncLocalStorage` (`node:async_hooks`) request context & W3C `traceparent` propagation; 5-key error envelope translation; Vitest/Jest testing; and graceful `SIGTERM`/`SIGINT` shutdown with 30s connection draining.
- **Python & FastAPI Standard Scope**: Python 3.11+ type hints (`mypy --strict` / `ruff`); `uv` / `Poetry` lockfile sync (`uv sync --frozen`); strict async event loop hygiene (`async def` exclusively for async I/O, `def` threadpool offloading); Pydantic v2 `ConfigDict(extra='forbid')` mass-assignment defense; `pydantic-settings` with `SecretStr`; `@asynccontextmanager` `lifespan` resource lifecycle; `contextvars` request context & W3C `traceparent` propagation; 5-key error envelope exception handlers; and `pytest-asyncio` integration testing.
- **Clean Code & Maintainability Scope**: All 5 SOLID principles (SRP, OCP, LSP, ISP, DIP); pragmatic DRY & YAGNI; Sandi Metz AHA principle (Avoid Hasty Abstractions); early-return guard clauses to maintain cyclomatic complexity $\le 3$; strict file size bounds (200–300 LOC target, 400 LOC soft cap, 500 LOC hard ceiling, excluding auto-generated code and lockfiles); self-documenting code with intent-based comments (*why* over *what*); and 100% synchronization between code, inline docstrings, and external specs (OpenAPI 3.1 / Protobuf).
